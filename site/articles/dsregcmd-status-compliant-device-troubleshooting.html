Read three lines of dsregcmd before you open a ticket

Mathew Dailey · November 25, 2026

User blocked by a "require compliant device" policy on a device Intune says is compliant? Before you re-enroll anything, run dsregcmd /status as the signed-in user (not elevated) and read three lines.

The three lines

  1. AzureAdJoined (Device State). If NO, Conditional Access can't see the device at all.
  2. AzureAdPrt (SSO State). NO means no Primary Refresh Token, so the device claim never reaches the sign-in. Since Windows 10 21H1, the Attempt Status line under it gives you the error code.
  3. AzureAdPrtUpdateTime. If it's more than four hours old, the PRT isn't refreshing. Lock and unlock the device, then run it again.

Match it with the sign-in log

If the sign-in log's Device info tab shows no device ID, the problem is on the client, not in your policy.

Thirty seconds here can save a re-enrollment that never would have fixed it.

And if the device shows up fine but a device you didn't expect is getting through, check the tenant-wide default for devices with no compliance policy.
