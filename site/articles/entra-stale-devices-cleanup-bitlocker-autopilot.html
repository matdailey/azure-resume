Before you delete stale devices in Entra ID, check these two things

Mathew Dailey · November 25, 2026

Cleaning up stale devices in Entra ID? A delete is permanent, and it takes two things with it that people forget.

What a delete takes with it

  1. BitLocker recovery keys. They're stored on the Entra device object. Delete the object and the keys go too, with no way back. Export or confirm you no longer need them first.
  2. Windows Autopilot. If that hardware gets reused, deleting its Entra object can break self-deploying and pre-provisioning deployments (ZTDID mismatch). Compare your list against Get-MgDeviceManagementWindowsAutopilotDeviceIdentity before deleting.

A safer routine

  1. Find: Get-MgDevice -All, filtered on ApproximateLastSignInDateTime older than 90 days.
  2. Disable: Update-MgDevice with accountEnabled = $false. Users get blocked, so you'll hear about anything still in use.
  3. Delete: wait out a grace period, then delete only devices that are still disabled.

Note that some active devices have a blank timestamp, so don't treat "blank" as "stale."

Windows LAPS passwords live on the device object too, which is one more reason to get LAPS permissions sorted before cleanup.
