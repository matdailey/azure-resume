Why your Intune Remediation script "never finds an issue"

Mathew Dailey · November 25, 2026

Intune Remediation showing "Without issues" on every device, even ones you know are broken? Check the exit code before you check the logic.

How detection decides

The remediation script only runs when the detection script ends with exit 1. Any other exit code, including a script that throws or one that returns nothing, is treated as "issue not found."

Four habits that save hours

  1. End every path explicitly. exit 1 when the problem exists, exit 0 when it doesn't. Wrap the logic in try/catch so an error can't fall through to a silent pass.
  2. Write one short line of output (Write-Output) in each branch. It shows up as a column in the device status report, and the limit is 2,048 characters.
  3. Mind the encoding. If "Enforce script signature check" is on, save the script as UTF-8 without BOM.
  4. Test locally as SYSTEM before uploading (psexec -i -s powershell.exe). Most "works on my machine" bugs are user-context assumptions.

Bonus: free inventory

The output column is the cheapest fleet-wide inventory you have. Use it.

Win32 app detection scripts follow similar rules with one extra trap: anything written to STDERR marks the app as not installed.
